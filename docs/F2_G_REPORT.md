# F2-G HTTP ve panel — çalışma raporu

FR-ID/CATALOG/CHECKOUT/PAY/BILL; R1-07, R4-04/05/10; SEC-002/004. Migration 013 server-bound pure confirmation ve granular permission kayıtlarını ekler; önceki migration'lar değişmez. Mevcut Identity/Queue/Outbox/Idempotency/Migration yeniden yazılmadı. Identity repository'ye yalnız authoritative müşteri snapshot okuması eklendi.

`/admin/commerce` ve `/client/commerce` mevcut panel görsel dilini kullanır. Katalog/configuration/sepet/quote/order; wallet/topup/bank notice; proforma/PDF geçmişi; yönetici ürün/varyant/seçenek/addon/döngü/vergi/fiyat/maliyet/kur/promosyon/sağlayıcı mapping; sipariş, tahsilat, banka onayı ve tek kasa ekranları gerçek application service verisi kullanır. Formlarda tutarlar decimal string olarak alınır, JS BigInt/string ile minor'a dönüşür; parasal Number hesabı yoktur.

JSON sınırı `/api/v1/{admin|client}/commerce/` altında GET görünümleri ve POST prepare/execute'tur. Cookie CSRF + Idempotency-Key + server session + fresh step-up + action permission + customer scope zorunludur. Saf plan aktör/session/input/current state/plan hash ile bağlanır; son kullanıcı açık checkbox ile onaylar. Değişen veri/expiry/used/cross-actor/revocation execute'u reddeder. Hassas idempotency yanıtı AEAD şifrelidir; açıklama, secret, dosya veya müşteri bilgisi plaintext cache/log'a yazılmaz. Gerçek PayTR webhook her ortamda auditli ret döndürür; hiçbir public test callback endpoint'i yoktur.

5 gerçek MariaDB pure-confirmation güvenlik testi ve 8 gerçek HTTP senaryosu geçti: prepare iş kaydı yazmaz, bir kullanımlık/yanlış payload/expired/stale/actor, müşteri quote/order, değişmiş wallet, impersonation, login/step-up/CSRF/scope, komut replay, gerçek banka onayı→wallet ödeme→ready, protected PDF attachment ve başka müşteri fatura/sipariş/PDF reddi, kapalı gerçek callback, gerçek asset sunumu, staff ledger ve production mutation gate. Ek olarak bağımsız addon (3), ödenmiş iade (3), hesap/cüzdan para birimi dönüşümü (2), yerel outbox tüketimi (3) doğrulandı. Son yerel paket 174 test / 0 hata; önceki 94 korunur. Müşteri tarayıcı demosu teklif→açık onay→sipariş→cüzdan ödeme→READY_FOR_PROVISIONING olarak tamamlandı; masaüstü ve mobil görseller evidence/f2 altındadır. Yönetici işlemleri HTTP testleriyle doğrulandı; bütün yönetici formlarının manuel tarayıcı kabulü iddia edilmez.

014–019 yeni migration'lar sırasıyla ödenmiş iade/credit note, bağımsız addon, orijinal tahsilat ve şifreli banka kanıtı, tek cüzdan para birimi dönüşümü, tarihsel cüzdan iadesi FX ve yerel outbox fact receipt ekler. Hesap dönüşümü Identity ve Finance application service'lerini tek transaction'da koordine eder; açık mali kalemler fail-closed reddedilir, eski belgeler korunur ve müşteri oturumları iptal edilir. Para birimi dönüşümünün DB guard'ı tek kullanımlık application kaydı gerektirir. Source currency kasa ile target currency clearing ayrı fişlerdir. Ödenmiş iade orijinal kaynaklara orantılı telafi oluşturur; dış iade yalnız payable rezervidir. orders.ready yerel tüketimi HELD_FOR_F3, mail MAIL_HELD kalır; başarılı kuyruk tüketimi hizmet veya mail teslimi anlamına gelmez.

Sınırlar: GATE'ler OPEN; staging/production sentetik kur ve test fixture kabul etmez. Banka production finance release gate kapalıdır. İç rapor resmî muhasebe değildir. PayTR/VM/domain hizmeti çalışıyormuş gibi sunulmaz. Scope grant'i yoksa yöneticinin müşteri listesi boş olabilir; otomatik müşteri erişimi eklenmedi. Listelemeler 50 kayıt ve offset ile ilerler; konservatif confirmation kilitleri için büyük ölçek yük testi yapılmadı. PDF parser/antivirus tam sanitization beyanı yoktur.

Geri dönüş: 013 mevcut oturumları sonlandırır; yeniden giriş ve step-up gerekir. Kod+DB+APP_KEY+korumalı dosya snapshot birlikte restore veya forward-fix; destructive down yok. İşlem üretmiş canlı sisteme yalnız kod rollback'i uygulanmaz. Her aşamanın kanıtı `docs/evidence/f2/` altında, nihai kabul matrisi F2_REPORT'ta olacaktır.
